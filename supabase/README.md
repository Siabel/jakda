# 데이터베이스 변경 관리

`migrations` 폴더는 작은다음의 현재 스키마와 이후 변경 순서를 기록합니다.

## 새 Supabase 프로젝트

`migrations`의 SQL을 번호 순서대로 Supabase SQL Editor에서 실행합니다.

## 기존 운영 프로젝트

운영 데이터베이스에는 `001_baseline.sql`과 같은 구조가 이미 적용되어 있습니다. 따라서 기준 파일을 다시 실행하지 않고, 앞으로 추가되는 `002_*.sql`부터 순서대로 실행합니다.

`schema.sql`은 현재 전체 구조를 한 번에 확인하기 위한 스냅샷입니다. `add-*.sql`, `remove-*.sql`, `repair-*.sql` 파일은 마이그레이션 체계를 만들기 전에 수동으로 적용했던 변경 이력으로 보존합니다.

새 기능의 스키마 변경은 반드시 다음 번호의 새 파일로 추가하고, 이미 적용된 파일은 수정하지 않습니다.

## 할 일 보관함 적용

기존 운영 프로젝트에는 `002_add_todos.sql`을 Supabase SQL Editor에서 한 번 실행합니다. 이 파일은 사용자별 할 일, 일정 연결 상태와 RLS 정책을 추가하며 기존 기록은 변경하지 않습니다.

그다음 `003_data_integrity.sql`을 실행합니다. 기존 기록은 보존하면서 잘못된 사용자 간 일정 연결을 해제하고, 일정 시간·할 일 완료 상태·사용자 소유 관계와 `updated_at` 갱신을 데이터베이스에서도 보장합니다.
